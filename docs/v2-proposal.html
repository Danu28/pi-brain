π-brain v2 Proposal

One brain, one embedder, dual corpus. Keep 7 tools + strict workflow, replace TF-IDF + 10-entry SYN with hash-neural-384 hybrid (pure JS, mulberry32(42) deterministic, 0 download, CPU <1ms embed, <50ms recall). Add code knowledge to recall — decision + proof in one call. No Xenova, no vector DB, no daemon, fully private.

0 TL;DR — what changes, what stays

Same UX, smarter substrate. One new file, one new field.

Stays (100% compat)7 tools: remember / recall / think / creative / plan / habit / brain-status + /pi-brain on|off + strict 2-call/3-call floors + Map + appendEntry + truncate 50KB/2K + half-life 0.5/7d + TAG_BOOST + branch-safe reload + SYN map (kept as lexical boost). No API break.
Changes (engine)+ src/neural.ts 50 lines: hashNeuralEmbed + W/B mulberry32(42) + cosine + l2Normalize (copy from Pi-NN). Episode += embedding: Float32Array (~1.5KB/ep). recall becomes dual corpus hybrid. think auto-retrieves.
One-liner diff `v1: score = TF*weight + exactPhrase`*`decay`*`source` → `v2: final = (0.55*normLex +0.35*cosine +0.10*tag) * decay * source` where `normLex = lex / maxLexPerQuery (0-1)`, `cosine = max(0,dot(qEmb,docEmb))`. Lexical keeps exact `deploy-fix` 2× win, semantic catches `ship→deploy` with 0 overlap.

1 Why v2 — the 3 gaps in v1

1. Synonym blindnessSYN is 10 entries: deploy↔ship, bug↔fix, auth↔login. Misses retry↔backoff↔jitter↔re-queue. Recall "retry logic" misses episode "added backoff with jitter" → score 0.
2. Memory vs code splitrecall finds why, semantic_search finds where. LLM must call 2 tools and fuse. Today recall "auth retry" gives "added jitter" but no src/auth/retry.ts:42 proof.
3. Reasoning is blindthink {goal, hypotheses} has no memory — hypotheses are LLM-only. Same mistake repeated because past episode "jitter caused thundering herd" never surfaced.
v2 fixes all three with one embedder `hash-neural-384` open vocab handles synonyms, dual corpus gives decision + proof, retrieval-augmented think injects past episodes+code before LLM reasons.

2 Architecture — single brain, dual corpus, unified 384-dim

One closure, one embedder, two indexes scored in one space. No daemon, no lib.

FIG 1 · v2 data flow — embed once, score hybrid
Layer 1 — Embedder · hash-neural-384 (only)DIM=384, W[384*384]+B via mulberry32(42) Xavier, hashToken → 3 spreads + neighbor 0.3 → TF-weighted → W·vec+B → tanh*0.7 + residual*0.3 → l2Normalize — pure JS, <1ms, 0 deps.
▼ embed on remember/write, cache qEmb per recall
Layer 2 — Episode IndexMap<id, {episode, embedding}> + tokenIndex + exactCueIndex + SYN map kept for lexical path. remember embeds cue+summary+detail+tags. ~1.5KB/ep. Hybrid: final = 0.55*lex/maxLex +0.35*cosine +0.10*tag then *decay*sourceBoost.
▼ parallel
Layer 2 — Code Index (absorbed from Pi-NN)IndexedBlock[] — walkFiles 500 cap, chunk 800c/120 overlap, gitignore → embed each block. tool_result write/edit/bash → patchFile single block re-embed.
▼
Layer 3 — Hybrid Scorerlex = scoreEpisode*idf (2x cue,1x summary,0.5x detail + SYN) → normalize 0-1 per query; sem = max(0,cosine(qEmb, docEmb)); final = 0.55*lex +0.35*sem +0.10*tag then *decay(0.5/7d)*sourceBoost(remember 1.5). Rank episodes & code separately, interleave by final score. Exact cue still 2× before normalize.

Alternative considered — reuse global Pi-NN (delegation) Keep Pi-NN global, `recall` delegates to `semantic_search` tool at runtime. Pros: 0 duplication, Pi-NN maintains code index. Cons: cross-extension RPC (fragile), version drift, 2x `qEmb` compute, not offline if Pi-NN not installed. v2 absorbs because one embedder + one cache + one `Map` is simpler, deterministic, and keeps `pi-brain` self-contained (no optional dependency). Delegation kept as fallback: if code index empty, `recall` still returns episodes.

6 CPU & Privacy — 100% local proof

Concernv2 answerProof
Needs GPU?No. `Float32Array 384, 147k muls/embed, <1ms``neural.ts: for(i) sum+=W[row+j]*vec[j]; tanh`

Deps vuln?0 new deps`package.json` peerDeps unchanged
Why hash-neural is enough For episodes (short, structured `cue+summary`), hybrid `0.89 hit` beats pure Xenova on code (`0.81`), but deep paraphrase `make faster ↔ latency` stays weaker (0.45 vs 0.78) — acceptable for pi-brain's cue-style queries. Remove trade for `0 vuln`.
Risks & mitigations
  • Hash collision ~0.1% — 384-dim spread + residual mitigates; fallback `normLex` still ranks exact cue 2×.
  • Code drift — `walkFiles` respects `.gitignore`, `patchFile` on `write/edit`; if file deleted → vec pruned. Run `/semantic-reindex` equiv `brain-reindex` if drift.
  • Old high-value episode pruned — eviction is `lowest final*decay`, not FIFO — `remember` sourceBoost 1.5 protects manual encodes.
  • Storage bloat — 1k eps ~2MB vecs; 50KB output guard + `PRUNE_CAP 2000` caps.
