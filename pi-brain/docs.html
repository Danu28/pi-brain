1 Architecture one file

The whole hippocampus is a Map rebuilt from the branch. No class, no DI container — the factory closure is the container.

FIG 1 · factory → closure → branch-backed state
export default function(pi: ExtensionAPI)One closure owns episodes: Map<string, Episode>. Called once at startup via jiti (pi -e or auto-discovery). No async factory — state rebuilds from persisted branch.
▼
Episode { id, cue, summary, detail?, ts, source }id = cue:Date.now() · cue is the associative key (2× weight in recall) · ts for recency tie-break · source: "remember" | "auto"
▼durable, not in LLM context
pi.appendEntry("brain:episode", ep)Stored in .pi/sessions/… as type:"entry" entryType:"brain:episode". Never sent to LLM unless explicitly injected. Survives fork/resume/reload. Appends never overwrite → no withFileMutationQueue needed.
▼waking recall
pi.on("session_start", (_ev, ctx) → ctx.sessionManager.getBranch())episodes.clear() then scan branch: handles both entry (brain:episode) and legacy toolResult detail shapes. Uses fresh ctx arg — never caches stale manager (fork safety).

Entry vs LLM context — the key split

Pi has two stores. Pi-brain exploits both:

  • Entries (appendEntry) = long-term memory. Durable, not in LLM context, shown in TUI via registerEntryRenderer("brain:episode") (collapsed cue, expanded detail). Like hippocampal engrams.
  • Tool results = working context. Only surfaced to LLM when we explicitly return content: [text] or inject via before_agent_start. Like PFC working memory (~4 items).
Why not a file or DB? Pi already persists entries in session files. Adding a vector DB would duplicate storage and require a new infra — rejected in T01. Substring/BM25 over Map is enough (ponytail ladder).

Storage limits (myelination analog)

const MAX_BYTES = 50 * 1024;
const MAX_LINES = 2000;
function truncate(t: string) → cut
  lines>2000 → slice + note
  bytes>50KB → slice + note

Same ceiling pi uses (pi-tools §6). Keeps compaction from failing — metabolic collapse if unbounded.

// recall ranking — TF-IDF lite
tokens = tokenize(query)
score = Σ term TF * weight (cue 2, summary 1, detail 0.5)
       + exact phrase bonus
sort by score desc, then ts desc
// ponytail: O(n) scan, index if >10k

No startup index; lazy on each recall. Sparse coding: only scored episodes bubble up.

2 How it works lifecycle

From cue in to episode out: the perception-action loop mirrored in pi's event lifecycle.

FIG 2 · encode → store → recall → consolidate loop (hippocampal loop)
Encode: remember {cue, summary, detail?} → pi.appendEntry + Map.set + pi.events.emitExplicit encoding (study). Also auto-encodes every successful edit/write/bash via tool_result (first 200 chars) — lightweight, no LLM call.
▼durable entry, TUI renderer shows collapsed cue
Before each turn: before_agent_start injects 3 most recent episodesPFC working memory analog — {message:{role:"system", content:"Recent brain episodes:\n- cue: summary"}}. Only if episodes exist; no provisional empty inject.
▼
During turn: input gate + context pruneinput normalizes @path (thalamus routing). context keeps system + last 20 if >40 msgs (synaptic pruning — drop low-value toolResults).
▼on demand
Recall: recall {query, limit?} → O(n) scored ranking → truncated text + details.episodesCue 2×, summary 1×, detail 0.5×; recency tie-break; fallback to recency if no score >0. Lazy — no index at startup.
▼offline, like sleep
Consolidate: session_before_compact → inject top 5 episodes into summaryHippocampal replay — replaces raw transcript injection with curated episodes + original summary. No episodes → keep default. Hooks existing compaction, no extra LLM call.

3 How to use pi -e

Seven tools. Call them from the model or from a prompt — SKILL.md tells the model when.

Install & run

One-off (try it)pi -e ./pi-brain/index.ts
Tools appear in pi.getAllTools(). No npm install, no build.
Auto-discovery (keep it)Copy to ~/.pi/agent/extensions/pi-brain/index.ts or .pi/extensions/pi-brain/index.ts (project, needs trust). Then /reload or restart.

Tips

  • Cue design: short kebab keys (deploy-fix, auth-bug) score 2× in recall — beats long sentences.
  • No startup index: recall is lazy O(n); add an index only if >10k episodes (ponytail note in code).
  • Fork safety: episodes survive fork/resume/reload via branch scan; use fresh ctx arg, never cache old manager.
  • Truncation: all outputs bounded to 50KB/2K; no metabolic collapse from large episodes.
  • Cache: all tools are promptSnippet-free → system prompt prefix stays stable, provider cache hits.
Calibration knob Truncation limits (MAX_BYTES/MAX_LINES) and prune threshold (40 msgs → keep 20) are plain constants at top of index.ts — tune like myelination thickness for your provider/context window. Minimal model, knob stays.

4 Brain → extension map one row, one pi mechanism

Every brain principle maps to exactly one pi surface — no wrapper that just renames a stdlib call. If a row didn't change agent behavior, it was deleted (design §2).

8 characteristics → extension behavior

1 · Plasticity → plain Map + appendEntry

Strengthen used paths (recall 2× cue), no recompile. Add habit as SKILL.md when a path repeats.

2 · Parallel & distributed → pi's concurrent tool calls

Score over Map while other tools run; pi already parallelizes sibling calls — no custom scheduler.

3 · Hierarchical + predictive → stacked handlers

input → before_agent_start → context → before_provider_request chain in load order; only prediction-carrying injections propagate.

4 · Sparse & energy-efficient → sparse activation + truncate

Only 3 recent injected, top 5 in compaction, ranked recall; 50KB/2K ceiling beats GPU watts-per-inference.

5 · Associative memory → recall (BM25/substring)

Partial cue retrieves whole episode; no index lookup — pattern completes via score + recency.

6 · Consolidation during rest → session_before_compact

Hippocampus replays top 5 at compact; cortex (prompt) slowly absorbs. Offline, lossy → generalization (feature).

7 · Embodied & grounded → edit/write/bash auto-encode

Cognition coupled to motor output; every successful effector leaves an engram without explicit remember.

8 · Metacognition → brain_status + cingulate patch

Watches itself: getContextUsage reports load; error monitor appends recall hint; knows when it doesn't know.
